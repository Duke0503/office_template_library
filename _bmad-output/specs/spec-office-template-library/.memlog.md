- (direction) Source is docs/reference/brief.md (recruiter take-home brief, Vietnamese). Express distill chosen: input is rich, no guided elicitation.
- (decision) Integrated editor is ONLYOFFICE Document Server Community Edition run in Docker; it edits both DOCX and PPTX. User confirmed 2026-10-29.
- (decision) One application with one template engine generic over document kind; DOCX and PPTX are two kinds of the same model, not two codebases, so XLSX can be added later.
- (decision) Delivery is local: one docker compose command starts everything; no hosted deployment (brief requires runnable, not hosted).
- (constraint) Deadline 2026-11-01 15:00 (UTC+7); effort budget 6-8 h; brief rewards quality, runnability and clarity over feature breadth.
- (capability) CAP-1 Browse gallery: user sees templates of one kind as a grid with thumbnail, name, short description and category.
- (capability) CAP-2 Search and filter: user narrows the gallery by free-text search and by category; no match shows an empty state.
- (capability) CAP-3 Preview: user opens a template preview before using it; DOCX shows the rendered document, PPTX shows every slide.
- (capability) CAP-4 Create from template: user clicks Use template and gets a new independent document copied from it; the original file stays byte-identical.
- (capability) CAP-5 Edit: user edits the new document in the integrated editor in the browser; saved changes persist to that document only.
- (capability) CAP-6 Download: user downloads the document as DOCX or PPTX; it opens in Word/PowerPoint/LibreOffice with basic formatting intact.
- (capability) CAP-7 My documents: user sees documents created earlier, reopens them in the editor or downloads them.
- (capability) CAP-8 Template management: an operator adds or updates a template (file plus metadata) and it appears in the gallery with no UI code change or rebuild.
- (capability) CAP-9 States: every screen shows explicit loading, error, empty and not-found states; an unknown template or document id gives a not-found page, not a crash.
- (capability) CAP-10 Seed data: the app ships with at least 5 DOCX templates and at least 3 PPTX template sets, each with thumbnail and previews, loaded automatically on first start.
- (constraint) Template originals are immutable: no code path opens a template file for writing; editing always targets a copy.
- (constraint) Template data model holds at least id, kind, name, category, description, file path and preview image(s) (brief II.C).
- (constraint) Only DOCX and PPTX are accepted; files are addressed by server-side id, never by a client-supplied path.
- (constraint) Third-party libraries and their licenses are disclosed; ONLYOFFICE Community is AGPL-3.0 and is run as a separate unmodified service.
- (constraint) AI-assisted development (Claude Code, BMAD Method) is disclosed in the handoff docs (brief IV).
- (constraint) Templates and sample data are self-authored or permissively licensed; no employer or client material (brief VIII).
- (decision) Non-goals: user accounts/auth, hosted deployment, template authoring UI, XLSX support (extension point only), real-time multi-user collaboration as a feature.
- (assumption) Single anonymous user; brief is silent on auth, so no login and no per-user isolation.
- (assumption) Template management is via a manifest plus seed/import command and an API, not an admin UI.
- (assumption) Thumbnails and slide previews are generated from the template files, not drawn by hand.
- (assumption) UI language is English.
- (question) Should the UI be English or Vietnamese (the reviewers are Vietnamese)?
